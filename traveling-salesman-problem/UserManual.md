# User Manual: High-Performance TSP Solver

## Requirements

- **Compiler:** g++ with C++17 support. The Makefile forces -O3 optimization to avoid artificially hitting the runtime wall prematurely. This is necessary with O(!n) permutation complexity.

- **Operating System:** Linux

- **Input File:** *distances.txt* must be present in the project root directory. It contains 380 floating-point edge weights.

## Building the Project

### Compile the Code

```bash
make
```

Generates object files and links them into the tsp_solver executable using -O3 flags.

### Remove Build Artifacts

```bash
make clean
```

## Program Execution & Input

1. Ensure *distances.txt* is present in the root directory
2. Launch solver

```bash
./tsp_solver
```

The system will interactively prompt you for the Genetic Algorithm configuration parameters:

- **Population Size:** The number of individual tours in a single generation. (100-500 recommended)

- **Generations:** The fixed number of iterations before the algorithm terminates. (500-2000 recommended)

- **Mutation Percentage:** What percentage of a generation should be comprised of mutations. Enter as a whole integer (10 for 10%, etc.)

Once configured, the program requires no further interaction. It automatically scales the hardware stress test starting at 10 cities, incrementing by 1 until the brute force permutation phase exceeds a runtime of 5 minutes (300 seconds)

## Program Output and Data Collection

The console output is strictly formatted for data extraction. The program generates a table containing the 6 data points required for the Results.xlsx deliverable.

For each city increment, it outputs:

1. **Cities:** Current n value being evaluated

2. **Optimal Cost:** Absolute lowest-cost route determined by brute force search

3. **BF Time (s):** Execution time of the brute force algorithm

4. **GA Cost:** Lowest cost found by the Genetic Algorithm

5. **GA Time (s):** Execution time of the Genetic Algorithm

6. **% Optimal:** A metric showing how close the GA heuristic came to the optimal solution

## Enginering Details

### Brute Force Engine

- **Algorithm:** Uses the mandated perm1() iterative permutation generator

- **Mechanics of Permutations:** Evaluating (n−1)! permutations relies heavily on caching. Permutations are generated in-place without heap allocations.

## Genetic Algorithm Mechanics

- **Elitism:** The system algorithmically guarantees that exactly one elite tour is preserved unmodified and carried into the next generation

- **Crossover:** Implements Order Crossover (OX1) to splice permutations without visiting a city twice or dropping one by accident

- **Mutation:** Randomly selects 2 to 4 cities and swaps their positions to maintain genetic diversity and avoid minima

## Memory Architecture

- **Graph Storage:** The complete graph is flattened into a continuous 1D array (std::array) sized for 400 elements. This works with the CPU's L1 cache, allowing a large number of distance lookups to execute by brute force with very low latency.
